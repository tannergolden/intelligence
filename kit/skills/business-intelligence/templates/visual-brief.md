# Visual brief (the ★ Chief Data Officer fills this before dispatching)

A self-contained brief the lead writes in Phase 0 and threads into every dispatch (the Visualization Designer, the quality-assurance skill's Design Critic, and the Data Analyst when the data needs cleaning), so whichever agent acts works to the real request rather than improvising it (`references/visual-dispatch.md`).

- **Request:** [what the user asked for, verbatim or close, or "proactive" when the response itself called for it]
- **Question the visual must answer:** [the one thing a reader should take away]
- **Data or content:** [the numbers with their ranges, the structure, or the concept; note the source, whether it is clean, and whether the analysis verified it]
- **Audience and medium:** [who reads it, where it renders, chat or a saved file]
- **Chosen form and why:** [the single form, with the one-line reason it fits the question, from the form-by-question table in references/principles.md]
- **Integrity constraints:** [zero baseline, honest scale, no forbidden encoding; any data caveat]
- **Accessibility floor:** [contrast, a color-vision-deficiency-safe palette, never color alone, a text alternative]
- **Tier:** [quick | standard | interactive]
- **Home:** [a named save location, or "chat only" if it is a leaving visual]
